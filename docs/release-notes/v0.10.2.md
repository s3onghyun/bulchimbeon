## English

**Lid-closed mode was broken in 0.10.0 and 0.10.1.** Every lid-closed watch was logged as
"approval denied" even after you entered the administrator password, and fell back to
`caffeinate -i`, but `pmset disablesleep 1` had already run. Lid sleep stayed disabled with the
app unaware, so the Mac would not sleep with the lid closed, even after the watch ended.
**Everyone on 0.10.0 or 0.10.1 should upgrade.**

> **If you used lid mode on 0.10.0/0.10.1**
>
> 1. Run `pmset -g | grep SleepDisabled`.
> 2. If it shows `1`, quit and reopen Bulchimbeon (or run `sudo pmset -a disablesleep 0`).
> 3. Run `pmset -g | grep SleepDisabled` again; it should show `0`.

### Highlights

- **Lid-closed duty works again.** The enable command's `pkill` no longer matches and kills
  the administrator-prompt `osascript` that ran it. Cancelling the password prompt and an
  approval failure are now told apart; a failure records its cause and how to retry in the
  duty log and a notification. If only the result is lost but lid sleep is disabled and the
  watcher is running, the app takes ownership and restores sleep when the watch ends. (#57)
- **The menu states the effective mode.** During a watch the first menu line shows what this
  watch keeps (for example "Display off · Mac stays awake"); during a fallback the reason is
  shown under the duty mode. A fallback is never saved as the chosen mode. (#57)

Linux daemon: no change.

### Install

- **macOS:** `brew update && brew upgrade --cask bulchimbeon`, or
  `brew install --cask s3onghyun/tap/bulchimbeon` for a new install. Or download
  `Bulchimbeon-0.10.2.zip` below.
- **Linux:** Homebrew, tarball, `.deb` and `.rpm` installation instructions are in
  [Linux → Install](https://github.com/s3onghyun/bulchimbeon#install-1). Pick one method only,
  so that only one daemon runs.

Verify any release file with its published SHA-256 checksum, then run
`gh attestation verify <file> --repo s3onghyun/bulchimbeon`.

Full list of changes: [CHANGELOG.md](https://github.com/s3onghyun/bulchimbeon/blob/v0.10.2/CHANGELOG.md).

## 한국어

**0.10.0 과 0.10.1 에서 덮개 닫힘 근무가 고장 나 있었습니다.** 관리자 암호를 넣어도 매번 "승인 거부" 로 기록되고
`caffeinate -i` 로 대체됐지만, 그 전에 `pmset disablesleep 1` 은 이미 실행된 뒤였습니다. 앱은 모른 채 덮개 잠자기
해제가 남아, 근무가 끝난 뒤에도 덮개를 닫아도 맥이 잠들지 않았습니다.
**0.10.0·0.10.1 을 쓰는 분은 모두 업그레이드하세요.**

> **0.10.0·0.10.1 에서 덮개 근무를 썼다면**
>
> 1. `pmset -g | grep SleepDisabled` 를 실행하세요.
> 2. `1` 이 보이면 불침번을 종료했다가 다시 여세요 (또는 `sudo pmset -a disablesleep 0`).
> 3. `pmset -g | grep SleepDisabled` 를 다시 실행해 `0` 인지 확인하세요.

### 주요 변경

- **덮개 닫힘 근무가 다시 됩니다.** 켤 때의 관리자 명령에 든 `pkill` 이 그 명령을 실행한 암호 창 `osascript` 를
  죽이지 않습니다. 암호 창 취소와 승인 실패를 가려, 실패는 원인과 다시 하는 법을 일지·알림에 남깁니다. 결과만 끊기고
  덮개 잠자기 해제와 감시병이 확인되면 앱이 소유해 근무가 끝날 때 원복합니다. (#57)
- **메뉴가 실제 근무 방식을 보입니다.** 근무 중 메뉴 첫 줄은 이번 근무가 지키는 것(예: "화면은 꺼짐 · 맥만 깨어 있음")을
  보이고, 대체 근무 중에는 근무 형태 아래에 까닭을 보입니다. 대체 근무는 고른 방식으로 저장되지 않습니다. (#57)

리눅스 데몬: 변경 없음.
