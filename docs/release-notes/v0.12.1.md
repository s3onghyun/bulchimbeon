## English

**Agent watch no longer keeps the Mac awake for idle sessions.** Bulchimbeon could stay on duty
after every agent had finished: Claude Code sessions left waiting at the prompt still counted as
working when they had long-running helpers around them, such as MCP servers, hook scripts that
poll in the background, or a Stop hook that waits for the next message. Now an agent counts as
working only on its own recent activity.

### Highlights

- **"Working" means recent activity.** An agent is working when it and the processes it started
  in the last 10 minutes use at least 2% CPU (60-second average). Processes that have run longer,
  such as MCP servers (about 0.3%) and background pollers (about 1%), no longer add up. One of them
  still counts if it alone uses 5% or more, so a long build keeps the watch.
- **Claude Code's `caffeinate` needs a fresh tool run beside it.** Claude Code runs
  `caffeinate -i -t 300` while a turn is in progress, and a Stop hook that waits for hours keeps the
  turn open. The `caffeinate` child now counts only while a tool or hook started in the last
  10 minutes runs next to it (Claude Code stops tool calls and command hooks after 10 minutes by
  default).
- **Helper sessions are judged on their own.** A `claude -p` session started under another agent,
  for example by a hook, no longer adds its CPU to the session that started it.
- **The old behaviour is one toggle away.** To keep the Mac awake whenever an agent is open, turn
  on **Agent watch settings ▸ Count idle sessions as working** (`agentWatchCountsIdle`, unchanged).
  The 5-minute grace before handover is unchanged too.
- **`--diagnose` says why.** For each agent it measures CPU for 5 seconds and shows the rule that
  decided it: the `caffeinate` child and whether it counts, the agent's own CPU, the busiest
  recent and long-running processes with their age, and whether another agent started it. It never
  prints command lines or environment variables. On Linux, the `Why:` line of `bulchimbeon status`
  names the rule.
- **The menu-bar private stops animating while it cannot be seen** (screen locked, display asleep or
  the menu bar covered) and slows down in Low Power Mode. (#69)

**What may feel different:** after real work, a session whose Stop hook goes back to waiting is
handed over within 10 minutes plus the grace time. A tool call that waits more than 10 minutes
without using CPU (a long `sleep`, waiting for CI) no longer counts on its own. Claude Code's own
`caffeinate` still keeps the Mac awake during that wait.

This release is not marked critical. The bug wasted power but did not lose data or weaken
security, and the battery floor and heat safeguards kept working throughout.

### Install

- **macOS:** use "New version 0.12.1 — Update" in the menu (0.11.0 and later), or
  `brew update && brew upgrade --cask bulchimbeon`, or
  `brew install --cask s3onghyun/tap/bulchimbeon` for a new install. Or download
  `Bulchimbeon-0.12.1.zip` below.
- **Linux:** Homebrew, AUR, tarball, `.deb` and `.rpm` installation instructions are in
  [Linux → Install](https://github.com/s3onghyun/bulchimbeon#install-1). Pick one method only,
  so that only one daemon runs.

Verify any release file with its published SHA-256 checksum, then run
`gh attestation verify <file> --repo s3onghyun/bulchimbeon`.

## 한국어

**에이전트 근무가 쉬는 세션 때문에 맥을 깨워 두지 않습니다.** 에이전트가 모두 일을 마쳤는데도 불침번이 근무를
계속할 수 있었습니다. 입력을 기다리는 Claude Code 세션이라도 MCP 서버, 뒤에서 폴링하는 hook 스크립트, 다음 메시지를
기다리는 Stop hook 처럼 오래 도는 도우미가 곁에 있으면 일하는 중으로 셌습니다. 이제 에이전트 자신의 최근 활동만 봅니다.

### 주요 변경

- **"일하는 중"은 최근 활동입니다.** 에이전트와 그 에이전트가 최근 10분 안에 띄운 프로세스가 CPU 2% 이상(60초 평균)을
  쓸 때 일하는 중입니다. MCP 서버(약 0.3%)나 뒤에서 폴링하는 루프(약 1%)처럼 그보다 오래 돈 프로세스는 더는 합치지
  않습니다. 그중 하나가 혼자 5% 이상 쓰면 여전히 세므로 긴 빌드는 근무를 유지합니다.
- **Claude Code 의 `caffeinate` 는 최근 시작한 도구 실행과 함께여야 합니다.** Claude Code 는 턴이 진행되는 동안
  `caffeinate -i -t 300` 을 띄우는데, 몇 시간씩 기다리는 Stop hook 도 턴을 열어 둡니다. 이제 `caffeinate` 자식은 최근
  10분 안에 시작한 도구·hook 실행이 곁에 있을 때만 셉니다 (Claude Code 는 도구 실행과 command hook 을 기본 10분에 끊습니다).
- **도우미 세션은 따로 판단합니다.** hook 같은 것이 다른 에이전트 아래에서 띄운 `claude -p` 세션의 CPU 를 띄운 세션에
  더하지 않습니다.
- **예전 방식은 토글 하나입니다.** 에이전트가 열려 있기만 해도 맥을 깨워 두려면 **에이전트 근무 설정 ▸ 열려만 있는
  세션도 근무로 인정**(`agentWatchCountsIdle`, 그대로)을 켜세요. 교대 전 유예 시간 5분도 그대로입니다.
- **`--diagnose` 가 까닭을 보입니다.** 에이전트마다 CPU 를 5초 동안 재서 판단한 규칙을 보입니다: `caffeinate` 자식과
  인정 여부, 에이전트 자신의 CPU, 가장 바쁜 최근·오래된 프로세스와 실행 시간, 다른 에이전트가 띄웠는지. 명령줄과
  환경변수는 출력하지 않습니다. 리눅스에서는 `bulchimbeon status` 의 `Why:` 줄이 규칙을 보입니다.
- **메뉴바 이등병은 보이지 않는 동안 움직이지 않고**(화면 잠금, 디스플레이 절전, 메뉴바가 가려짐) 저전력 모드에서는 천천히
  움직입니다. (#69)

**달라 보일 수 있는 점:** 실제로 일한 뒤 Stop hook 이 다시 기다리기 시작한 세션은 10분 + 유예 시간 안에 교대합니다.
CPU 를 쓰지 않고 10분 넘게 기다리는 도구 실행(긴 `sleep`, CI 대기)은 그것만으로는 세지 않습니다. 그동안에는 Claude Code
자신의 `caffeinate` 가 맥을 깨워 둡니다.

이 릴리스는 중요 수정으로 표시하지 않았습니다. 이 버그는 전력을 낭비했지만 데이터를 잃거나 보안을 약하게 하지 않았고,
배터리 하한과 폭염 대응은 그동안에도 그대로 작동했습니다.
