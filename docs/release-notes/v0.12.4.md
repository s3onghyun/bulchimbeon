## English

**Lid sleep is now restored when the Mac restarts or shuts down during a lid watch.** On 2026-11-13 a
restart during a lid watch left the Mac unable to sleep with the lid closed for 28 hours 40 minutes. If
you restarted or shut down your Mac while the lid watch was on, this affected you too. There were four causes:

1. The root watchdog that guards the lid watch had no signal handling. A restart or shutdown sends it
   SIGTERM, and it died without turning lid sleep back on.
2. The relaunched app took the leftover `disablesleep` flag as a running lid watch, but the watchdog was
   tied to the old app, so nothing guarded the new one.
3. In that state the menu hid **⚠️ Restore lid sleep**, while the notification told you to click it.
4. When the app quit, it did not wait for the watchdog to finish restoring.

Now the watchdog restores lid sleep as soon as it receives SIGTERM, SIGHUP or SIGINT. On logout, restart
and shutdown the app waits up to about 7 seconds for that restore, without an admin password prompt. If
the flag is still set when the app starts again, the watch continues as a system watch, the flag is left
as it is and the menu shows **⚠️ Restore lid sleep**. Picking the lid watch again asks for admin approval
and starts a new watchdog. The notification now says that restoring needs the admin password. (#81)

**No more false "⚠️ Last watch ended abnormally" after a quick relaunch** (seen 2026-10-28). When the app
restarted quickly, for example after changing the language or updating, the new app read the flag before
the old watchdog had restored it. The app now waits up to about 7 seconds for a still-running old watchdog
before deciding. (#81)

**Notarization is prepared but not active yet.** The release workflow now has Developer ID signing, Apple
notarization and stapling steps. They run only once signing secrets exist. This build is still ad-hoc
signed like before, so the first-launch steps are unchanged: allow it once under System Settings → Privacy &
Security → **Open Anyway**. (#80)

The menu and usability changes that are waiting for review come in 0.12.5.

### Install

- **macOS:** use "New version 0.12.4 — Update" in the menu (0.11.0 and later), or
  `brew update && brew upgrade --cask bulchimbeon`, or
  `brew install --cask s3onghyun/tap/bulchimbeon` for a new install. Or download
  `Bulchimbeon-0.12.4.zip` below.
- **Linux:** the Linux engine got the same rule for a leftover lid flag. The Linux daemon does not handle the
  lid, so you will not notice a difference. Homebrew, AUR, tarball, `.deb` and `.rpm` installation instructions
  are in [Linux → Install](https://github.com/s3onghyun/bulchimbeon#install-1). Pick one method only, so that
  only one daemon runs.

Verify any release file with its published SHA-256 checksum, then run
`gh attestation verify <file> --repo s3onghyun/bulchimbeon`.

Full list of changes: [CHANGELOG.md](https://github.com/s3onghyun/bulchimbeon/blob/v0.12.4/CHANGELOG.md).

## 한국어

**덮개 근무 중 맥을 재시동하거나 끄면 이제 덮개 잠자기가 원래대로 돌아옵니다.** 2026-11-13, 덮개 근무 중 재시동한 뒤
맥이 덮개를 닫아도 28시간 40분 동안 잠들지 않았습니다. 덮개 근무를 켠 채 맥을 재시동하거나 끈 적이 있다면 같은 문제를
겪었을 수 있습니다. 원인은 넷이었습니다.

1. 덮개 근무를 지키는 root 감시병에 신호 처리가 없었습니다. 재시동·시스템 종료가 보내는 SIGTERM 을 받으면 덮개
   잠자기를 되돌리지 않고 죽었습니다.
2. 다시 실행된 앱이 남은 `disablesleep` 플래그를 진행 중인 덮개 근무로 이어받았지만, 감시병은 옛 앱에 묶여 있어 새
   앱을 지키는 감시병이 없었습니다.
3. 이 상태에서 메뉴는 **⚠️ 덮개 잠자기 복구** 버튼을 숨겼는데, 알림은 그 버튼을 누르라고 안내했습니다.
4. 앱이 끝날 때 감시병의 복구를 기다리지 않았습니다.

이제 감시병은 SIGTERM·SIGHUP·SIGINT 를 받는 즉시 덮개 잠자기를 되돌립니다. 로그아웃·재시동·시스템 종료 때 앱은 그
복구를 최장 약 7초 기다리며, 관리자 암호 창은 띄우지 않습니다. 그래도 플래그가 남은 채 앱이 다시 시작되면 근무는 시스템
근무로 이어지고, 플래그는 그대로 두어 메뉴에 **⚠️ 덮개 잠자기 복구**가 보입니다. 덮개 근무를 다시 고르면 관리자 승인을
받고 새 감시병을 띄웁니다. 알림에도 복구에 관리자 암호가 필요하다고 적었습니다. (#81)

**빠르게 다시 실행해도 "⚠️ 지난 근무 비정상 종료" 오경보가 뜨지 않습니다** (2026-10-28 실사용). 언어 변경·업데이트처럼
앱이 빨리 다시 실행되면, 옛 감시병이 원복하기 전에 새 앱이 플래그를 읽고 경고했습니다. 이제 옛 감시병이 살아 있으면
최장 약 7초 기다린 뒤 판단합니다. (#81)

**공증 준비는 끝났지만 아직 켜지지 않았습니다.** 릴리스 워크플로에 Developer ID 서명·Apple 공증·staple 단계를
넣었습니다. 서명 비밀값이 생겨야 작동합니다. 이번 빌드도 전처럼 ad-hoc 서명이라 첫 실행 절차는 같습니다: 시스템 설정 →
개인정보 보호 및 보안에서 **그래도 열기**를 한 번 누르세요. (#80)

검토 중인 메뉴·사용성 개선은 0.12.5 에 들어갑니다.
