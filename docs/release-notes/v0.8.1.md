## English

### Highlights

- **Linux suspend fix.** On GNOME (and other desktops whose power manager suspends as
  you, such as Cinnamon), earlier Linux releases could let the desktop suspend automatically while agents were working: the logind lock they held is ignored for
  your own user's suspend on systemd 256 and older (Ubuntu 24.04, Debian 12), which is how
  the desktop's power manager suspends. 0.8.1 asks the desktop itself
  (`org.gnome.SessionManager.Inhibit` on GNOME, Cinnamon, MATE and Budgie;
  `org.freedesktop.PowerManagement.Inhibit` on KDE). Verified on Ubuntu 24.04 GNOME.
  **Linux users should upgrade.** (#44)
- **Screens still lock.** The idle lock is gone: the screen dims, turns off and locks as
  configured, while the machine stays awake.
- **XFCE is opt-in.** XFCE's power manager treats any inhibitor like presentation mode, so by
  default Bulchimbeon does not block its automatic suspend, and `status` and `doctor` say so.
  `bulchimbeon config set xfceKeepAwake true` blocks it, at the cost of the screen staying on
  and unlocked while on duty.
- **Headless unchanged.** Without a desktop (headless, SSH, sway, Hyprland) the daemon keeps a
  logind `sleep` lock, now `block-weak` on systemd 257 and later so your own suspend still works.
- **Tray.** Off duty, the tray icon goes Passive, so KDE moves it into the overflow area; it
  comes back to the panel when duty starts.
- `bulchimbeon status` and `doctor` show which method holds the lock and why.

### Known limitations

- Closing the lid still suspends.
- Over SSH or on a headless machine, the sleep block needs a polkit rule (`bulchimbeon doctor` prints it).
- On sway and Hyprland, an idle daemon that suspends as you is not stopped.
- The desktop inhibitor covers your own session only; another user's session can still suspend.

macOS: no change.

### Install

- **macOS:** `brew update && brew upgrade --cask bulchimbeon`, or
  `brew install --cask s3onghyun/tap/bulchimbeon` for a new install. Or download
  `Bulchimbeon-0.8.1.zip` below.
- **Linux:** Homebrew, tarball and `.deb` installation instructions are in
  [Linux → Install](https://github.com/s3onghyun/bulchimbeon#install-1). Pick one method only,
  so that only one daemon runs.

Verify any release file with its published SHA-256 checksum, then run
`gh attestation verify <file> --repo s3onghyun/bulchimbeon`.

Full list of changes: [CHANGELOG.md](https://github.com/s3onghyun/bulchimbeon/blob/v0.8.1/CHANGELOG.md).

## 한국어

### 주요 변경

- **리눅스 절전 수정.** GNOME(그리고 Cinnamon 처럼 전원 관리자가 사용자로 절전하는 데스크톱)에서 이전 리눅스 릴리스는 에이전트가 일하는 중에도 데스크톱이
  자동 절전하게 둘 수 있었습니다. 잡고 있던 logind 잠금은 systemd 256 이하(Ubuntu 24.04, Debian 12)에서
  사용자 본인의 절전 요청에는 무시되는데, 데스크톱 전원 관리자가 바로 그렇게 절전합니다. 0.8.1 은
  데스크톱에 직접 요청합니다 (GNOME·Cinnamon·MATE·Budgie 는 `org.gnome.SessionManager.Inhibit`,
  KDE 는 `org.freedesktop.PowerManagement.Inhibit`). Ubuntu 24.04 GNOME 에서 확인했습니다.
  **리눅스 사용자는 업그레이드하세요.** (#44)
- **화면은 그대로 잠깁니다.** `idle` 잠금을 없애, 화면은 설정대로 어두워지고 꺼지고 잠기며 컴퓨터는 깨어 있습니다.
- **XFCE 는 선택.** xfce4-power-manager 는 어떤 억제든 프레젠테이션 모드처럼 다루므로, 기본으로는 자동
  절전을 막지 않고 `status`·`doctor` 가 그렇게 알립니다. `bulchimbeon config set xfceKeepAwake true` 로
  막을 수 있지만, 근무 중에는 화면이 켜진 채 잠기지 않습니다.
- **헤드리스는 그대로.** 데스크톱이 없으면(헤드리스·SSH·sway·Hyprland) logind `sleep` 잠금을 쓰고,
  systemd 257 이상에서는 `block-weak` 라 내가 하는 절전은 그대로 됩니다.
- **트레이.** 근무 중이 아니면 트레이 아이콘이 Passive 가 되어 KDE 는 넘침 영역에 둡니다. 근무에 들어가면 패널에 다시 보입니다.
- `bulchimbeon status`·`doctor` 가 어떤 방법으로, 왜 잠금을 쥐었는지 보여줍니다.

### 알려진 제한

- 덮개를 닫으면 여전히 절전합니다.
- SSH·헤드리스에서 절전 막기는 polkit 규칙이 필요합니다 (`bulchimbeon doctor` 가 출력).
- sway·Hyprland 에서 사용자로 절전하는 idle 데몬은 막지 못합니다.
- 데스크톱 억제는 내 세션만 다룹니다. 다른 사용자의 세션은 절전할 수 있습니다.

macOS: 변경 없음.
